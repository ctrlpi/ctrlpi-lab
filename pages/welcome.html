Welcome to ctrlPi

What is ctrlPi?

ctrlPi lets you control Raspberry Pi, Pico W, and ESP32 GPIO pins and read named sensors over a REST API, from a dashboard, command line, or integration.

Architecture

One tiny server per board. Everything else talks to it over plain HTTP on your LAN.

Agents: the muscle
A single-file REST server on the Pi, Pico W, or ESP32 drives the pins: outputs, inputs, pull-ups, pulses with auto-revert, reversed relay logic, and webhooks on every change. Same API across boards, clients never care which one answered.
Bridges: the home
Matter and native-HomeKit bridges declare your devices in one JSON file: lights, locks, garage doors, valves, sensors, buttons, and drive them through the agents' API. Pair once, control from your phone, your watch, or "Hey Siri".
MCP: the brain
A zero-dependency Model Context Protocol server exposes the whole GPIO surface as tools. Ask Claude to scan your LAN for agents, flip a relay, or watch a door sensor, in plain language.

Small pieces, one wire format: every connection is plain HTTP with an Api-Key header, no hubs or clouds required.

What is ctrlpi-lab?

ctrlpi-lab is the browser workbench for your ctrlPi setup. It provides a lightweight, zero-dependency local dashboard that communicates with your agents over HTTP through an internal proxy:

  • API Tester: test every GPIO, sensor, and configuration endpoint directly from the browser with dynamic form controls, response inspection, and instant cURL examples.
  • Live Logs: inspect and tail agent logs in real time with keyword search and category filtering.
  • Webhook Monitor: monitor live events and notifications delivered to public test or local webhook endpoints.
  • Automatic Discovery: sweeps your local subnet for online agents, saves credentials securely, and keeps your agent list in sync with all ctrlPi tools.
  • Shared Ecosystem: shares configuration with mcp-bridge and smart-home bridges, allowing AI assistants (like Claude) to connect to your agents using the same saved credentials.

Key capabilities

  • Read and write GPIO pins by number or configured name alias
  • Configure pins as input, output, VCC (always HIGH), or GND (always LOW)
  • Timed output pulses with automatic revert: duration is capped by max; when duration is omitted, a configured max supplies it
  • Active-low (reversed) logic, with logical value and physical level reported separately
  • Watch inputs for state changes and outputs for writes; send events to configured webhook and bridge targets, or log them when no target is configured
  • Read named sensors on demand using scripts: shell scripts on Pi, MicroPython scripts on Pico and ESP32
  • Read, update, and load configuration, with automatic backups before updates and loads

Quick start

Install an agent using the instructions below. In the header, select a discovered agent or click + to add its IP address or hostname, port (default 8314), and API key. Use the key icon to edit the saved key, then explore endpoints in the API tab or open API - cURL Examples.

The agents serve plain HTTP. Keep them on a trusted LAN; use a tunnel for remote access rather than exposing port 8314 to the internet.

Install the API on a Raspberry Pi

Requires Python 3.9+ on Raspberry Pi OS. Supported boards: Raspberry Pi 2, 3, 4, 5, Zero W, and Zero 2 W. Run these commands in a terminal on the Pi.

Install with curl

curl -fsSL https://raw.githubusercontent.com/ctrlpi/pi-gpio-api/main/install.sh | bash cd pi-gpio-api ./run.sh

The installer downloads the project, builds its virtual environment, and asks for an agent name and API key if no config exists. The server listens on all interfaces at port 8314 by default.

To run at boot, copy the ready-to-paste systemd command printed by the installer. To change and save the API key when starting the server:

./run.sh --api-key your-secret-key --save

See the Pi API installation guide for GPIO backend requirements and more options.

Install the API on a Raspberry Pi Pico

Requires a Pico W or Pico 2 W, MicroPython firmware, and a Mac/PC connected to the board over USB. Run the tools below on your computer, not on the Pico.

Easiest: Pico Bay

npx @ctrlpi/pico-bay

Connect your board and choose Install ctrlPi API from the top-right menu. Enter your API key and WiFi information when prompted. Pico Bay can also install MicroPython when the board is connected in BOOTSEL mode, or after choosing Reboot to BOOTSEL.

Or install with curl

curl -fsSL https://raw.githubusercontent.com/ctrlpi/pico-gpio-api/main/install.sh | bash

With MicroPython already installed, the installer asks for any missing API key, agent name, and WiFi credentials, copies the files to every connected Pico over USB using mpremote, and resets the boards. Existing device configuration is preserved on a normal reinstall.

The API starts automatically at every boot on port 8314. The original Pico W requires an http:// webhook target; Pico 2 W also supports https://.

See the Pico API installation guide for firmware, WiFi, and USB deployment details.

Install the API on an ESP32

Requires an ESP32, ESP32-C3 or ESP32-S3 with MicroPython 1.29 firmware (the matching ESP32_GENERIC build), and a Mac/PC connected to the board over USB. Run the tools below on your computer, not on the ESP32.

Easiest: Pico Bay

npx @ctrlpi/pico-bay

Connect your ESP32 and choose Install ctrlPi API from the top-right menu. Enter your API key and WiFi information when prompted.

Or install with curl

curl -fsSL https://raw.githubusercontent.com/ctrlpi/esp32-gpio-api/main/install.sh | bash

With MicroPython already installed, the installer asks for your API key, agent name, and WiFi credentials, compiles bytecode, and deploys to the board over USB.

The API starts automatically at boot on port 8314.

See the ESP32 API installation guide for details.

Install and connect ctrlPi MCP Bridge

An MCP (Model Context Protocol) server that gives AI assistants like Claude Desktop full control over your GPIO agents in natural conversation, with zero dependencies.

Add to Claude Desktop (no install required)

Open Claude Desktop settings, click Developer → Edit Config, and add ctrlpi under mcpServers:

{ "mcpServers": { "ctrlpi": { "command": "npx", "args": ["-y", "@ctrlpi/mcp-bridge"] } } }

Restart Claude Desktop. On first launch, it sweeps your local /24 subnet for agents and records them in ~/.ctrlpi/agents-config.json.

Run as an HTTP service (for remote clients and integrations)

npx -y @ctrlpi/mcp-bridge --http

Or install it in a folder of your choice:

npm install @ctrlpi/mcp-bridge cd node_modules/@ctrlpi/mcp-bridge npm start -- --http

Listens on port 8315 and shares configuration with ctrlpi-lab in ~/.ctrlpi/agents-config.json.

See the MCP Bridge documentation for PM2 service configuration, key rotation, and tool details.
